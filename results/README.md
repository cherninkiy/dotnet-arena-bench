# Результаты прогонов

Здесь лежат **все** полные прогоны, на которые ссылаются отчёты PoC. Каталог
устроен одинаково для каждого стенда и каждого прогона:

```
results/
  <stand>/<run>/
    allocator/        # ArenaBench.Allocator.Bench — 241 кейс
      BenchmarkRun-*.log
      results/        # *-report-github.md, *.csv, *.html
    serialization/    # ArenaBench.Serialization.Bench — 122 кейса
      BenchmarkRun-*.log
      results/
  <stand>/MANIFEST.md
  <stand>/REPLICATION.md   # только для стенда B
  <stand>/SHA256SUMS
```

`archive-2026-10-24-short-run/` — пилотный `--job short` (3 итерации), не
используется в итоговых таблицах; сериализация там оборвана после трёх классов.

## Два стенда — два статуса

| Стенд | Статус | Машина | Прогоны |
|---|---|---|---|
| [`stand-a-2026-10-22-win11-7800x3d`](stand-a-2026-10-22-win11-7800x3d/MANIFEST.md) | **final**: на этих числах построены таблицы | Windows 11, Ryzen 7 7800X3D, x86-64-v4 | 1 полный прогон каждого проекта |
| [`stand-b-2026-10-24-linux-4800h`](stand-b-2026-10-24-linux-4800h/MANIFEST.md) | **provisional replication** | Ubuntu 24.04.5, Ryzen 7 4800H, x86-64-v3 | 2 полных прогона каждого проекта |

**Абсолютные значения между стендами смешивать нельзя.** Медиана
`abs(stand B − stand A)` по совпавшим кейсам — 68.3–68.7 % для аллокатора и
54.3–54.5 % для сериализации. Это разные CPU, ОС, JIT-архитектура и governor.
Сравнимы только **отношения внутри одного стенда**; переносимость направления
проверяется по `REPLICATION.md`, а не вычитанием наносекунд.

## Что именно проверялось на стенде B

Повторяемость двух прогонов (run1 против run2, все кейсы):

| Проект | Кейсов | Медиана `abs(δ)` | p95 `abs(δ)` | `abs(δ) > 10 %` |
|---|---:|---:|---:|---:|
| allocator | 241 | 0.86 % | 9.39 % | 11 / 241 |
| serialization | 122 | 0.60 % | 5.41 % | 3 / 122 |

Это повторяемость **внутри** стенда B, а не согласие со стендом A. Классы с
худшим p95: `MarkReleaseBench` 31.1 %, `SolverParallelBench` 22.7 %,
`AllocSingleBench` 15.9 %, `SolverCsrBench` 12.8 %. На стенде B не удалось
поднять приоритет процесса (`Failed to set up high priority`), а governor —
`schedutil`; поэтому стенд B и помечен provisional.

## Что хранится в git

Тяжёлые отчёты (`results/**/results/`) и `*.log` остаются локальными и
перечислены в `.gitignore`. В репозитории отслеживаются только `README.md`,
`MANIFEST.md`, `REPLICATION.md` и `SHA256SUMS`: по ним можно проверить
происхождение и целостность локальной копии, не коммитя несколько мегабайт
HTML/CSV.
